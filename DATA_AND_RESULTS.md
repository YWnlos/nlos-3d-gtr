# Data and Result Index

This document maps the released datasets and experiment directories to the
figures in the 3D-GTR paper and supplementary material. Paths are relative to
this directory.

## What each experiment directory contains

Every directory under `real_output/` contains an experiment record:

- `used_config.yaml`: the exact configuration saved for that experiment;
- one or more `.pth` checkpoints, normally `final_model.pth` and, where used,
  a pruned or merged variant;
- one or more `resample_pred_trans_128x128*.mat` files containing the dense
  virtual-wall transient generated by 3D-GTR;
- a `.png` image produced by the downstream LCT or RSD reconstruction used for
  the paper figure.

Some historical filenames differ, for example `final_prune_model_merged.pth`,
`final_model_merged_2.pth`, or epoch-numbered checkpoints in `speed_quality/`.
Treat the filenames present in each directory as the authoritative experiment
record. The current scripts use stable names for new runs.

The `.pth` model and synthesized `.mat` transient are outputs of this codebase.
The final volumetric reconstruction is not: LCT and RSD implementations are not
included here.

## Supplementary Figure S3: speed-quality trade-off

`real_output/speed_quality/` contains checkpoints and RSD reconstructions for
5, 10, 15, 20, 25, 30, 40, and 50 epochs. All use
`real_data/real_trans_dataset_ncwall_O_random3000.mat`. The paper reports a
batch size of four and approximately 0.9 seconds per epoch for this experiment.

## Historical inactive configuration fields

The experiment configurations remain otherwise unchanged for provenance. They
include development-only adaptive-density, regularization, augmentation, and
normal-cycling fields that had no effect on the reported results. The current
training code ignores those fields. See the `Historical configuration keys`
section of `README.md` for the complete list.
